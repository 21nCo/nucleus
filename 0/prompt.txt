`@21n/shared-data` only depends on `@datafn/core`, so this module cannot name those types without adding a SearchFn dependency. Call sites already check the shape: IndexedDB and OpenSearch adapters take `defaults` / `pipeline` on construct.

`as const` is doing two things instead of an annotation:

- Keeps literals (`prefix: true`, `fuzzy: 1`, boosts as exact numbers) for the index-version hash.
- Does **not** check the object against SearchFn. A typo like `prefx` or `enableSteming` would still compile here and only fail later when passed into an adapter.

If you want both, `satisfies SearchDefaults` / `satisfies PipelineOptions` is the fit: still `as const`-narrow, but validated. That would mean a type-only SearchFn import on this package, which it currently avoids.
